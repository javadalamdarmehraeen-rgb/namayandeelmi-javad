 راهنمای یک‌بار تنظیم گیت‌لب + کار روزمره با دو سیستم (دو کامپیوتر)
════════════════════════════════════════════════════════════════

هدف: با هر بار اجرای یک دستور، فایل‌های پروژه هم‌زمان روی گیت‌هاب و گیت‌لب
به‌روز شوند و هر دو کامپیوتر شما همیشه آخرین نسخه را داشته باشند.

────────────────────────────────────────
الف) تنظیم گیت‌لب — فقط یک بار لازم است
────────────────────────────────────────
۱) وارد gitlab.com شو و یک پروژه خالی بساز (مثلاً namayandeelmi-javad).
   مهم: تیک ساختن README را نزن؛ پروژه باید کاملاً خالی باشد.

۲) در پوشه برنامه روی سیستم اول (کنار SYNC_ALL.bat) این دستور را بزن — فقط یک بار:

   git remote add gitlab https://gitlab.com/USERNAME/namayandeelmi-javad.git

   (به‌جای USERNAME نام‌کاربری گیت‌لب خودت را بنویس)

۳) اولین push به گیت‌لب نام‌کاربری و رمز می‌خواهد. گیت‌لب رمز عادی قبول نمی‌کند؛
   باید یک «توکن دسترسی» بسازی:
   در گیت‌لب:  User Settings → Access Tokens → افزودن توکن جدید
   نام دلخواه + تیک read_repository و write_repository → Create
   آن رشته طولانی را کپی کن و همان را به‌جای رمز وارد کن.
   (این توکن را در جای امن نگه دار؛ وارد هیچ فایل پروژه نکن.)

۴) دستور زیر را یک بار بزن تا شاخه main روی گیت‌لب هم ست شود:

   git push -u gitlab main

────────────────────────────────────────
ب) کار روزمره — روی هر دو سیستم
────────────────────────────────────────
پایان کار روی هر سیستم، فقط همین را اجرا کن:

   ویندوز:   SYNC_ALL.bat v11.15.3 توضیح تغییرات
   لینوکس/مک: sh sync_all.sh v11.15.3 توضیح تغییرات

این اسکریپت به ترتیب: pull از گیت‌هاب → pull از گیت‌لب → ثبت تغییرات →
push به گیت‌هاب → push به گیت‌لب.

قانون طلایی دو سیستم: قبل از شروع کار روی سیستم دوم هم یک بار SYNC_ALL را
اجرا کن تا آخرین نسخه سیستم اول را بگیرد؛ یعنی «اول بگیر، بعد عوض کن، آخر بفرست».

────────────────────────────────────────
ج) چیزهایی که هرگز وارد گیت نمی‌شوند (قفل شده در .gitignore)
────────────────────────────────────────
• .env و هر فایل env واقعی (توکن/رمز) — فقط قالب example مجاز است.
• node_modules — برنامه بدون آن هم با «node server.js» اجرا می‌شود.
  حذف امن روی ویندوز:   rmdir /s /q node_modules
  حذف امن روی لینوکس/مک: rm -rf node_modules
• server-db.json (داده زمان اجرا) و فایل‌های *.zip

نکته: بررسی تاریخچه گیت (۱۴۰۵/۰۵/۲۵) نشان داد هیچ فایل .env واقعی تاکنون وارد
گیت‌هاب نشده است. اگر روزی فایل اشتباهی وارد گیت شد، بلافاصله رمزهایش را عوض کن.

────────────────────────────────────────
د) آینه خودکار گیت‌لب → گیت‌هاب (اختیاری)
────────────────────────────────────────
فایل .gitlab-ci.yml پروژه یک مرحله mirror دارد: اگر در تنظیمات CI/CD گیت‌لب
دو متغیر GITHUB_TOKEN و GITHUB_REPO_URL را ست کنی، بعد از هر push به گیت‌لب،
گیت‌هاب هم خودکار به‌روز می‌شود. با اسکریپت SYNC_ALL این کار لازم نیست؛
اختیاری است.
