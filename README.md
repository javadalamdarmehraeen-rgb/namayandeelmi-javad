# ثبت اطلاعات کل

سامانه ثبت اطلاعات داروخانه، پزشک، سفارشات و رصد تردد نمایندگان علمی.
Next.js 16 (App Router) + PostgreSQL (Drizzle ORM) + PWA (قابل نصب روی ویندوز، اندروید و iOS).

## دسترسی پیش‌فرض

| نقش | نام کاربری | رمز عبور | شماره همراه ورود |
| --- | --- | --- | --- |
| مدیر | `admin` | `admin1234` | `09120000000` |
| نماینده نمونه | `rep1` | `rep1234` | `09121111111` |

> با متغیرهای محیطی `ADMIN_PASSWORD` و `ADMIN_PHONE` می‌توانید مقدار اولیه مدیر را تغییر دهید
> (فقط در اولین اجرای دیتابیس خالی اعمال می‌شود). بعد از ورود، از مسیر «نمایندگان و دسترسی» رمز را عوض کنید.

## اجرای محلی (VS Code)

```bash
npm install
# فایل .env
# DATABASE_URL=postgresql://user:pass@host/db?sslmode=require
npm run dev
```

جدول‌ها در اولین اجرا **به صورت خودکار** ساخته می‌شوند (نیازی به اجرای migration نیست).

## استقرار روی Render + Neon

### چرا خطای «Could not find a production build» می‌گیرید؟

در لاگ Render فقط این خط دیده می‌شود:

```
==> Running 'npm start'
```

و **هیچ خطی از `npm run build` وجود ندارد** → یعنی فیلد **Build Command** سرویس شما خالی است.
`next start` فقط سرور را اجرا می‌کند و خودش بیلد نمی‌سازد، به همین دلیل پوشه‌ی `.next` وجود ندارد.

### راه‌حل قطعی (۲ دقیقه)

Render → سرویس شما → **Settings** → بخش **Build & Deploy**:

| فیلد | مقدار درست |
| --- | --- |
| Root Directory | خالی (اگر پروژه در ریشه‌ی ریپو است) |
| Build Command | `npm install --include=dev && npm run build` |
| Start Command | `npm run start` |
| Health Check Path | `/api/health` |

سپس **Environment** → افزودن متغیرها:

| Key | Value |
| --- | --- |
| `DATABASE_URL` | رشته اتصال Neon، مثلا `postgresql://user:pass@ep-xxx.neon.tech/neondb?sslmode=require` |
| `APP_SECRET` | یک رشته تصادفی طولانی |
| `NODE_VERSION` | `20.18.0` |
| `NPM_CONFIG_PRODUCTION` | `false` |

در آخر **Manual Deploy → Clear build cache & deploy**.

> نکته: `--include=dev` لازم است چون Render مقدار `NODE_ENV=production` می‌گذارد و در این حالت
> `npm install` بسته‌های toolchain (typescript و tailwind) را نصب نمی‌کند و بیلد می‌شکند.

### شبکه‌ی ایمنی (اگر باز هم Build Command را فراموش کردید)

اسکریپت `npm start` این پروژه به `scripts/start.mjs` وصل شده است: اگر پوشه‌ی `.next` موجود نباشد،
**خودش قبل از اجرای سرور یک بار `next build` می‌گیرد** و بعد روی `PORT` مربوط به Render بالا می‌آید.
پس حتی با تنظیمات ناقص هم سرویس live می‌شود (فقط اولین بوت کندتر است).

### استفاده از Blueprint

فایل `render.yaml` در ریشه‌ی پروژه همه‌ی این تنظیمات را دارد؛ کافیست در Render گزینه‌ی
**New → Blueprint** را بزنید و ریپو را انتخاب کنید، سپس فقط `DATABASE_URL` را وارد کنید.

### تشخیص سریع مشکل

آدرس `https://<your-app>.onrender.com/api/health` را باز کنید:

- `{"ok":true,"db":true}` → همه‌چیز سالم است.
- `{"ok":false,"reason":"DATABASE_URL تنظیم نشده است"}` → متغیر محیطی را اضافه کنید.
- `{"ok":false,"reason":"..."}` → متن خطا مشکل اتصال Neon (معمولاً نبودن `?sslmode=require`) را نشان می‌دهد.

## امکانات

- ورود با نام کاربری/رمز + بررسی شماره همراه فعال روی همان گوشی و هشدار در صورت مغایرت یا آفلاین بودن سیم‌کارت.
- ورود جداگانه مدیر و داشبورد کامل مدیریتی.
- سه کلید اصلی نماینده: ثبت اطلاعات داروخانه، ثبت اطلاعات پزشک، ثبت سفارشات داروخانه.
- تاریخ شمسی خودکار + تقویم انتخابی + ماسک تایپی (`۱۴۰۵/۰۱/۰۱`).
- ثبت لوکیشن نقطه‌ای روی نقشه به نام همان داروخانه/پزشک و نمایش آن با کلیک روی نام.
- لیست‌های کشویی قابل جستجو و تایپ (تخصص، پخش، ویزیتور) که مدیر به صورت لحظه‌ای اضافه/حذف می‌کند.
- صفحات نمایش با ستون «ردیف» و «نام نماینده» و کلید «ارسال اطلاعات» برای مدیر.
- ثبت تردد روی نقشه به صورت آنلاین و آفلاین (صف محلی + همگام‌سازی خودکار)، ساعت شروع، ثبت وقفه و پایان سفر.
- ارسال خودکار سفارش به بله، ایتا و واتساپ (شماره یا گروه، با امکان فعال/غیرفعال‌سازی).
- خروجی اکسل (CSV با انکودینگ UTF-8 مخصوص Excel) از همه بخش‌ها.
- مدیریت کاربران، رمز عبور، شماره همراه ورود و سطح دسترسی.
- رصد فعالیت لحظه‌ای نمایندگان.

## 📲 ساخت فایل APK با PWABuilder

همه پیش‌نیازها به‌صورت خودکار آماده می‌شوند:

- اسکریپت `prebuild` پیش از هر build اجرا می‌شود و آیکون‌های `96…1024` پیکسل،
  نسخه‌های `maskable` (۱۹۲ و ۵۱۲)، `apple-touch-icon` و سه اسکرین‌شات را
  از روی لوگوی SVG می‌سازد. بنابراین حتی اگر فایل‌های PNG هنگام انتقال به مخزن
  یا سرور جا بمانند، روی Render دوباره ساخته می‌شوند.
- علاوه بر آن، مسیرهای پویا (`/icons/[file]`, `/screenshots/[file]`,
  `/apple-touch-icon.png`) به‌عنوان لایه دوم محافظ، تصویر را در لحظه تولید می‌کنند
  تا هرگز خطای ۴۰۴ رخ ندهد.
- سرویس‌ورکر با یک اسکریپت درون‌خطی در `<head>` بلافاصله ثبت می‌شود تا ابزارهای
  بررسی PWA آن را تشخیص دهند.

### مراحل گرفتن APK

1. تغییرات را روی Render منتشر کنید (Build Command: `npm install --include=dev && npm run build`).
2. در [PWABuilder.com](https://www.pwabuilder.com) آدرس **صفحه اصلی** سایت را وارد کنید (نه `/login`).
3. دکمه Retest را بزنید؛ همه Action Items باید سبز شوند.
4. `Package For Stores → Android` یا `Download Test Package` را بزنید.

## 🌐 پایداری شبکه و کارکرد آفلاین (معماری)

**مشکل قبلی:** همه صفحات `force-dynamic` بودند، یعنی هر بار باز کردن هر صفحه نیاز به
پاسخ سرور داشت. روی اینترنت موبایل (و سرور رایگان Render که پس از بی‌کاری خاموش می‌شود)
این درخواست‌ها تایم‌اوت می‌کردند و برنامه بالا نمی‌آمد.

**راه‌حل اصولی:**

1. **همه صفحات استاتیک شدند** (`○ Prerendered`). پوسته برنامه دیگر هیچ وابستگی به سرور ندارد.
2. **پیش‌کش کامل** — سرویس‌ورکر (v8) در نصب اولیه هر ۳۴ مسیر برنامه را کش می‌کند.
3. **Cache-First برای صفحات** + بروزرسانی خاموش در پس‌زمینه → باز شدن آنی روی هر اینترنتی.
4. **مهلت کوتاه برای داده** (۶ ثانیه) و برگشت فوری به کش.
5. **صف آفلاین** روی IndexedDB برای همه نوشتن‌ها + همگام‌سازی خودکار.
6. **نشست محلی** (۱۴ روز) تا برنامه بدون سرور هم باز شود.
7. **`/api/ping`** فوق‌سبک (بدون دیتابیس) برای بیدار کردن سرور + پینگ هر ۴ دقیقه.

## 🔐 تایید سیم‌کارت (روش اصولی)

مرورگرها به دلایل امنیتی **اجازه خواندن شماره سیم‌کارت را نمی‌دهند**. روش استاندارد و
قابل اتکا، اثبات در دسترس بودن سیم‌کارت با **کد یکبارمصرف (OTP)** است:

1. نماینده نام کاربری/رمز را وارد می‌کند.
2. سامانه یک کد ۵ رقمی به **شماره ثبت‌شده توسط مدیر** پیامک می‌کند.
3. اگر آن سیم‌کارت داخل همان گوشی باشد، کد دریافت می‌شود → ورود انجام و **گوشی به حساب قفل می‌شود**.
4. اگر سیم‌کارت در گوشی نباشد، کدی نمی‌رسد → ورود ممکن نیست.
5. ورودهای بعدی از همان گوشی بدون کد انجام می‌شود؛ هر گوشی دیگری مسدود است.
6. مدیر می‌تواند از صفحه «کاربران» گوشی را **آزاد** کند (تعویض دستگاه).

### تنظیم سرویس پیامک
صفحه «پیام‌رسان‌ها» → بخش «سرویس پیامک»: کاوه‌نگار، SMS.ir، ملی‌پیامک یا آدرس سفارشی.
می‌توان با متغیرهای محیطی هم تنظیم کرد: `SMS_PROVIDER`, `SMS_API_KEY`, `SMS_SENDER`, `SMS_PATTERN`.

> اگر سرویس پیامک تنظیم نشده باشد، کد به‌صورت خودکار به **اعلان مدیر** ارسال می‌شود تا
> شفاهی به نماینده بدهد؛ بنابراین سامانه بدون پیامک هم کار می‌کند.

## 🩺 عیب‌یابی و پایداری روی اینترنت موبایل

### علت واقعی «فقط با وای‌فای کار می‌کند»
سرویس‌ورکر فقط صفحات HTML را کش می‌کرد اما **فایل‌های جاوااسکریپت (۱.۳ مگابایت) را نه**.
چون برنامه یک اپ React است، HTML بدون چانک‌های JS بی‌فایده است؛ روی وای‌فای سریع
دانلود می‌شدند ولی روی اینترنت موبایل تایم‌اوت می‌کردند → صفحه سفید.

**راه‌حل:** اسکریپت `scripts/build-sw.mjs` پس از هر build اجرا می‌شود، فهرست واقعی
همه چانک‌های `/_next/static` را می‌خواند و در سرویس‌ورکر ثبت می‌کند. حالا **۴۱ فایل
استاتیک + ۳۰ صفحه** به‌طور کامل پیش‌کش می‌شوند.

### صفحه عیب‌یابی
آدرس `/diagnostics` — ۱۰ آزمون زنده: نوع شبکه، سرویس‌ورکر، تعداد فایل‌های کش‌شده،
سرعت پاسخ سرور، دیتابیس، نشست آفلاین، شناسه دستگاه، GPS و صف آفلاین.
دکمه «پاک‌سازی و نصب مجدد» و «کپی گزارش» هم دارد.

## 🔐 کنترل سیم‌کارت — چهار حالت

مدیر برای **هر کاربر جداگانه** از صفحه «کاربران» یکی از این حالت‌ها را انتخاب می‌کند:

| حالت | رفتار |
|---|---|
| `بدون بررسی` | هیچ کنترلی انجام نمی‌شود |
| `تطبیق شماره` | شماره واردشده باید با شماره ثبت‌شده مدیر یکی باشد |
| `قفل گوشی` (پیش‌فرض) | علاوه بر شماره، حساب به اولین گوشی قفل می‌شود؛ گوشی دیگر مسدود |
| `تایید پیامکی` | سخت‌گیرانه‌ترین: با کد پیامکی اثبات می‌شود سیم‌کارت داخل همان گوشی است |

مدیر با دکمه «آزادسازی گوشی» می‌تواند اجازه تعویض دستگاه بدهد.
